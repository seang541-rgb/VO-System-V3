1. 项目定位

  • 浏览器内本地解析 IFC，不上传模型原始文件。
  • 做 QS / VO 场景的技术差异、商业拆分、Excel 底稿导出。
  • 使用 Supabase 做账号与点数控制，Stripe 做充值。
  • 商业动作遵循 Omission / Addition，不把 Modified 直接当计价动作。

2. 当前功能范围

  • 双 IFC 对比：Added / Deleted / Modified
  • 字段级 diff：属性、材质、type、pset、数量、几何摘要
  • QS 规则层：Shield / Formwork / Star Rate / EOT
  • SMM2 Section、QS Label、Location 映射
  • 商业动作：Omission / Addition、Qty / Unit / Rate / Amount
  • BQ 挂载控制台、Unit Mismatch 熔断
  • Excel：VO Cover Sheet、Summary、Star Rate Register、Build-up、VO Substantiation
  • 登录、额度扣费、Stripe 充值、Webhook 发货

3. 当前非目标

  • 不是完整企业级多项目平台
  • 不是完整 JKR / SMM2 全章覆盖
  • 不是精确实体布尔扣减引擎
  • 不是多人审批流系统
  • 不是合同管理 / ERP 全量替代

7. Supabase / Stripe 云端链路

阶段动作结果
登录Supabase Auth 登录进入真实工作台
导出consume_credit 校验并扣 1 次额度成功才允许生成 Excel
充值发起create-checkout跳转 Stripe Checkout
支付完成Stripe 调用 stripe-webhook验签 + 校验商品 + 幂等 + 加 50 credits
回跳 UI前端识别 ?checkout=success短轮询刷新余额并显示成功提示

  • 费率：项目费率要用真实合同价替换

14. 建议上线顺序

  1. 确认 Supabase SQL 前置、RLS、RPC 已执行。
  2. 部署 `create-checkout` 和 `stripe-webhook`。
  3. 在 Stripe Dashboard 配置生产 webhook。
  4. 把生产 `SITE_URL`、`whsec_...`、live key 写入 Supabase secrets。
  5. 重新部署 Edge Functions。
  6. 前端切换生产环境变量并打包。
  7. 做一笔真实或沙盒 end-to-end 支付测试，确认 `+50 credits` 与 UI 刷新。
