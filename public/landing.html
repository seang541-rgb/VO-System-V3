不是做“模型 viewer”，而是做商业动作引擎

系统重点不是把 IFC 看出来，而是把模型语言转换成合同语言和计价动作，让 QS 能直接进入挂载、核价、出表、追索赔。

Diff Engine

技术差异直接落到 Omission / Addition

所有技术 Modified 最终都会按商业动作拆成 Omission + Addition，避免出现“看得到修改，算不出钱”的断层。

  • GlobalId 对比
  • 材质 / type / pset / 属性 / 数量差异
  • 商业表里直接带 Qty / Unit / Rate / Amount
QS Logic

带 QS 灵魂的规则层

不是单纯几何 diff。系统会套 SMM2 风格的计量、Shield、Formwork、Star Rate、EOT 提示，先把漏财坑挡住。

  • Brickwork / Concrete opening shield
  • Formwork ripple-effect trigger
  • Forced Star Rate trapdoor
Commercial Output

直接导出底稿，不是只给 JSON

浏览器里跑完，直接导出 VO Cover Sheet、Summary、Star Rate Register、Build-up、VO Substantiation。

  • Excel 可继续手调
  • BQ Mapping Register 留痕
  • 客户可拿去内部评审或开会

为什么这套系统适合上线

当前版本已经具备对外演示、内部试点、受控上线的必要组件，尤其是支付闭环已经收口。

1

本地解析 IFC

模型核心数据留在浏览器端解析，不把 IFC 原始文件上传到云端。

2

云端点数控制

Excel 导出前先做云端额度检查和扣费，避免本地篡改。

3

Stripe 充值闭环

Checkout 发起、Webhook 发货、前端回跳刷新余额已经接通。

4

Webhook 幂等 + 商品校验

发货前不仅验签，还校验价格、币种、数量和 line item，避免误发点数。

安全与控制边界

这套商业化方案用“本地算模型、云端算额度”的方式收住了两个边界。

边界 处理方式
IFC 原始模型 本地浏览器解析，不依赖上传云端
点数扣费 Supabase RPC 云端扣减，前端不能直接改余额
充值发货 Stripe Webhook + 签名校验 + 幂等表
商品合法性 校验 price_id / currency / amount_total / quantity
未登录访问 AuthGuard 阻断，必须登录后进入工作台

典型工作流

这不是给 BIM 协调员的流程图，而是给 QS 与商业经理的实际使用路径。

步骤 用户动作 系统动作 商业结果
1 上传 Base / Revision IFC 浏览器端提取构件、材质、属性、数量、位置 生成可比对的 BimComponent 索引
2 点击 Run VO Comparison 技术 diff + QS 规则 + 商业拆分 得到 Omission / Addition / Star Rate / Shield 结果
3 进入 BQ Mapping 按 QS Label 做 BQ 挂载，校验单位 避免低价套用、拦截 Unit Mismatch
4 点击 Generate VO Excel 云端检查并扣除 1 次 premium audit 导出完整底稿包
5 额度不足时充值 Stripe Checkout + Webhook 发货 + 回跳刷新 余额增加 50，再次放行导出
