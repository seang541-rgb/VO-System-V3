视觉打磨范围 — 三个方案对比

根据你 9 周时间线和剩余功能工作量，选一个合适的范围

A

只动样式 · 1-2 天

改什么：配色、间距、字体、圆角、阴影、hover 动效

不改：组件结构、布局、文件拆分

优点：最快见效，不破坏现有逻辑，风险最低

缺点：App.tsx 还是 1400 行单体，后续改布局时要重来

适合的场景

  • 时间紧，只想让 demo 好看一点
  • 不打算近期改布局

留下的技术债

  • 单体文件难维护
  • 下次改布局还得重构
B

样式 + 组件拆分 · 3-5 天 ⭐ 推荐

改什么：A 的全部 + 把 App.tsx 拆成 Header / Sidebar / KPIGrid / ResultsTable / CopilotPanel 等独立组件

不改：整体布局（还是 sidebar + 3 tab 切换）

优点：视觉焕然一新 + 代码结构健康，后续加 onboarding / dashboard 都更容易

缺点：多花 2-3 天，但这是一次性投资

为什么推荐

  • QS 行业配色 + 专业质感一步到位
  • 1400 行拆成 ~8 个文件，每个 <200 行
  • 为 Phase 3🅱🅲 打好基础
  • 3-5 天在 9 周里占比很小

风险

  • 拆组件可能引入回归 bug
  • 需要跑全量 smoke test 验证
C

样式 + 拆分 + 布局重设计 · 1 周+

改什么：B 的全部 + 重新设计页面结构（比如 Copilot 常驻右侧 panel、3D 和表格同屏显示）

不改：后端逻辑、工具链路

优点：最接近"enterprise SaaS"的体验

缺点：耗时长、布局改动影响面大、需要反复调整

适合的场景

  • 准备给投资人/大客户 demo
  • 不急着做功能

风险

  • 占掉 9 周里的 1+ 周
  • BQ 定价、LLM 切换、流式响应都得排后面
  • 布局变动大，回归测试重
